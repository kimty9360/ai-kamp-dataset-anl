# 성능 개선 실행 계획과 확인 항목

최신 갱신: 배포 ZIP 원자료 연결로 0=양품·1=불량, LH/RH 제품 구분, 현재 CSV의 파일별 표준화 재현을 확인했다. 아래 계획의 초기 미확인 항목은 [최신 조사 기록](data_semantics_evidence.md)과 [연결 보고서](../artifacts/lineage_v1/report.md)를 우선 참고한다. 첫 개선 실험은 변경하지 않으며 다음 실험은 좌우 입력 추가로 분리한다.

## 1. 라벨·데이터 의미 확인

공식 원본과 로컬 CSV 일치는 기존 source_check.json에서 확인했다. 이는 의미 검증과는 다르다. 추가 조사 근거는 [데이터 의미 조사 기록](data_semantics_evidence.md)에 정리했다. 확정되지 않은 답을 추정해 학습 타깃을 바꾸지 않는다.

|확인 질문|현재 상태|확인 후 행동|
|---|---|---|
|PassOrFail에서 0과 1은 각각 무엇인가? 검사 기준은 무엇인가?|미확인|불량 라벨 확정 후 타깃 방향과 지표 재검토|
|CN7·RG3는 차종·제품·금형·설비 중 무엇인가?|가이드북 공개 사본에서 제품 구분 확인, 정확한 차종 연결 미확인|그룹별 모델 운영 기준 결정|
|한 행은 한 shot, 제품 하나, 또는 가공 기록인가?|미확인|중복의 의미와 독립 표본 단위 결정|
|동일 공정값에 반대 라벨이 붙은 이유는 무엇인가?|미확인|오류가 확인된 경우에만 별도 정정본 작성; 원본 보존|
|파일 행 순서는 시간·배치·라벨 정렬 중 무엇인가?|미확인|실제 시간/배치 정보가 있으면 추가 그룹 검증|
|표준화는 파일별인가? 원단위와 변환 계수를 받을 수 있는가?|미확인|물리적 차이·비율 변수의 타당성 판단|
|각 변수는 어떤 구간의 최대/평균이고 언제 확보되는가?|미확인|예측 시점 이후 정보가 입력에 섞이지 않도록 필터링|

팀에 위 질문을 공유하고, 답변과 근거 문서·날짜를 기록한다. 주최 측 문의는 사용자가 보낼 수 있도록 질문만 준비했으며 외부 메시지는 전송하지 않았다.

## 2. 예측 시점과 목표

잠정 개발 목표는 **공정 종료 후, 품질 검사 전 class_1 검사 우선순위**다. 10%는 기존 개발 예산이며 공식 평가 기준이나 현장의 확정 검사량이 아니다. 현재 최대값·사이클 시간 등은 공정 종료 전에 알 수 있다고 가정하지 않는다. 사출 시작 전 예측을 원하면 사용 가능한 입력을 다시 정하고 baseline부터 재평가해야 한다.

AP를 주 비교 지표로 유지하고 Recall@10%와 Precision·Recall·F1을 함께 본다. 실제 불량 방향 확인 전에는 불량률·불량 검출률이라고 부르지 않는다.

## 3. 파생변수 실험

CN7·RG3 각각, XGBoost balanced와 CatBoost balanced에 아래 후보를 적용한다. 원본 데이터·그룹·분할·시드는 baseline_v2 그대로다. 그룹은 파생변수 추가 전에 원본 입력으로 결정한다. 중복 삭제·라벨 수정·SMOTE·행 번호 입력은 하지 않는다.

- base: 기존 입력과 모델 설정 재현.
- temperature_differences: Mold_Temperature_3 - Mold_Temperature_4 및 인접 Barrel_Temperature 채널 5쌍의 차이.
- pressure_difference: Max_Back_Pressure - Average_Back_Pressure.
- shallower_tree: 원래 입력 그대로, 트리 깊이만 3에서 2로 변경.

차이는 제공된 표준화 값의 차이다. 실제 온도차·압력차를 뜻하지 않으며 이 변수를 채택할 근거는 기존 그룹 검증에서의 실험 결과다. 서로 다른 채널을 개별 표준화했다면 단위 해석이 더 제한된다. 비율은 0 근처와 음수 값 때문에 이번 후보에서 제외한다.

## 4. 작은 범위 튜닝과 선택

위 네 후보만 비교하고 파생변수와 깊이 변경을 조합하지 않는다. 각 외부 학습 폴드 안에서 기존 내부 그룹 OOF의 AP가 가장 높은 후보를 고른다. 동률이면 목록의 앞 후보를 선택한다. inner_selected가 이 선택 절차의 외부 평가다. 각 후보의 개별 평가도 함께 저장해 원인을 살펴본다.

전체 라벨의 EDA를 이미 본 뒤 만든 후보이므로 이 외부 평가도 완전한 독립 성능은 아니다. 좋은 외부 점수가 나올 때까지 후보를 계속 추가하지 않는다. 평균뿐 아니라 동일 seed/fold의 전후 차이를 paired_comparison.csv로 확인한다. 반복 폴드를 독립 표본으로 간주한 유의성 검정은 하지 않는다.

## 5. 임계값과 검사량

두 정책을 구분한다. 분류 정책은 0.5 고정과 내부 OOF F1 최대 임계값을 비교한다. 검사 우선순위는 각 외부 폴드에서 점수 상위 ceil(n×0.1)을 고르고 동점은 기존 tie_key를 따른다. AP·Recall@10%는 분류 임계값 변경으로 개선되지 않는다.

운영 기준을 정하려면 팀에서 ① 최대 검사 가능 비율 ② 놓침의 비용 ③ 오탐의 비용을 정해야 한다. 이후 내부 검증에서만 비용 또는 제약에 맞는 임계값을 고른다. 현재 inner_f1은 개발 기준일 뿐 최종 운영 기준이 아니다.

## 6. 추가 정보와 독립 평가

가능하면 기록 ID, 실제 생산 시각, 설비·금형·캐비티 ID, 원료 로트, 검사 결과 원본과 판정 기준, 센서 단위·표준화 계수, 생산 배치를 요청한다. 확보 즉시 입력으로 넣기보다 예측 시점에 알 수 있는지 먼저 확인한다.

독립 평가는 지금까지 보지 않은 기간/배치의 **라벨 있는 데이터**로 진행한다. 기존 전체 데이터를 보고 분석했으므로 지금 일부를 떼어도 완전히 새로운 테스트라고 주장할 수 없다. 미라벨 데이터만으로 정확도를 계산하지 않는다. 새 평가 데이터를 확보하면 후보·정책을 고정한 뒤 최종 평가하고, 그 결과로 재튜닝하면 또 다른 독립 평가가 필요하다.
