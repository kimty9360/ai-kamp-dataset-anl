## 확인된 사실

- labeled_data 7,996행에서 동일 ID 완전 중복 2,764행 제거 → 5,232개 기록. 공정값 결측 0개.
- CN7 3,974건/불량 28건, RG3 1,256건/불량 32건. JX1/SP2는 각각 양품 1건이므로 별도 참고용.
- CN7/RG3의 공정값 36개 중 각 제품 전체 좌우 기준 상수/모두 0인 12개를 기본 화면에서 제외 → 각각 24개. 원본은 유지한다.
- 동일 설비·시각의 LH/RH 공정값은 같아도 라벨은 다를 수 있다. 센서 3/4를 LH/RH로 해석하거나 2캐비티를 확정할 근거는 부족하다.
- 초기허용불량의 운영 정의와 실제 검사 시각은 미확인이다. 가스·미성형 원인은 단일 컬럼의 상관만으로 확정할 수 없다.
- CN7 10/29~30의 1,209건 중 검토 대상은 18건/16개 시각, 원본 라벨은 모두 Y다. 전체 날짜를 삭제하지 않는다.
- 18건 제외 시 사출–충전 시간 Pearson은 0.0951→0.9989, 배럴 온도1–2 Pearson은 0.9562→−0.0127. 이는 데이터 구성에 대한 민감도이며 오류/원인/모델 성능의 증명이 아니다.
- Average_Screw_RPM은 10/29 전후 약 292→29로 바뀌며 11/3에도 낮은 값이 유지된다. 단위·배율 미확인으로 보정하지 않았다.

## 대시보드 현재 동작

기본값은 원본 포함이다. 검토 대상 제외를 선택하면 CN7 전체 기간 기준 3,974→3,956건이 되고 불량 28건은 유지된다. 선택 행은 그래프·이동 통계·상관·CSV에 공통 적용된다. 검토 대상은 오류 확정/불량 재라벨링이 아니며 제외 모드에서도 원본 상세를 열 수 있다.

온도는 원본, 최근 5개/15개 이동 중앙값, 이동 표준편차(ddof=0)를 표시한다. 현재 관측 포함 과거 방향이며 선택 기간 시작·10분 초과 공백·결측에서 초기화한다. 미래 값은 사용하지 않는다. 사출 전 예측에 쓰려면 별도 시점 정렬이 필요하다.

## 다음 작업: 전처리 파이프라인 설계 (미구현)

1. 원본/기본 정리본/검토 이력/실험용 데이터를 분리하고 출처 해시와 규칙 버전을 기록한다.
2. 날짜·수치·ID·라벨 검사, 동일 ID 완전 중복 제거를 재현 가능한 단계로 만든다.
3. 차종·설비·좌우·시간 구간을 보존하고 검토 18건·RPM 문제를 별도 플래그로 관리한다.
4. 예측 시점과 목표를 정하고, 동일 이벤트 LH/RH가 분할 사이에 섞이지 않도록 시간 기반 평가를 설계한다. 평가 기간의 불량 수 부족을 먼저 해결한다.
5. 상수 제거·스케일링 등 학습 통계는 학습 분할에서만 산출한다. EDA 전체 자료 통계를 모델 전처리로 그대로 사용하지 않는다.
6. 금형 온도 평균/차이, 이동 통계, 사출−충전 시간 등을 소수 실험으로 비교한다. 원본 특성을 먼저 보존한다.
7. 검토 대상 포함/제외, RPM 포함/제외와 파생변수 실험을 분리해 기록한다. 극단값을 일괄 삭제하거나 미라벨을 모두 정상으로 가정하지 않는다.

## 저장 범위와 재현

GitHub에는 코드·출력 없는 현재 노트북·요약 CSV/그림·보고서·검증 기록을 보관한다. 원본 ZIP/PDF, 전체 행이 포함된 HTML, 검토 대상 행별 CSV, 모델 및 과거 실행 노트북은 로컬 전용이다. 과거 커밋에도 이전 노트북이 남아 있다. 보관 문서의 오래된 경로·결론은 당시 기록으로 읽는다.

[원본 배치 안내](../sources/README.md)에 따라 파일을 준비한 후 프로젝트 루트에서:

```bash
conda activate kamp-base
python 1.injection-molding/scripts/audit_cn7_oct29_30.py
python 1.injection-molding/scripts/build_dashboard.py
python -m http.server 8765 --bind 127.0.0.1 --directory 1.injection-molding/artifacts/dashboard_v1
```

브라우저: http://127.0.0.1:8765/ . GitHub에서 HTML을 바로 실행하는 서비스가 아니라 로컬 생성 방식이다.

Playwright 검증은 별도 테스트 환경이 필요하다. 기본 환경에 패키지를 추가하지 않고 임시 환경에서 수행했으며 `tests/verify_dashboard_browser.py`, `verify_temperature_trends.py`, `verify_review_mode.py`로 재현할 수 있다. 수치 대조·선택 범위·CSV·오프라인 사용을 검증했다.
