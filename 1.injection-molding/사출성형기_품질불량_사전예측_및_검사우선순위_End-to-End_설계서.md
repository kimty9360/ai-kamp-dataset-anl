## 1. 한 페이지 요약

### 1.1 해결하려는 문제

사출성형 공정이 끝난 뒤 최종검사에서만 불량을 확인하는 방식을 보완하기 위해, 공정 변수만으로 각 생산 건의 이상 위험 확률을 미리 예측한다. 모든 제품을 동일하게 검사하는 대신 위험도가 높은 건부터 검사하도록 우선순위를 만들고, 모델이 잘 맞는 조건과 실패하는 조건을 함께 분석한다.

### 1.2 최종 결과물의 형태

최종 시스템은 각 데이터 행에 대해 최소한 다음 값을 출력한다.

| 출력 | 의미 |
|---|---|
| `record_id` | 원본 행 추적용 식별자 |
| `product_group` | CN7 또는 RG3 |
| `failure_probability` | 보정된 이상/불량 확률 |
| `uncertainty_score` | 예측 불확실성 |
| `ood_score` | 학습분포 이탈 정도(선택) |
| `inspection_priority` | 검사 순번 |
| `risk_group` | 긴급/우선/일반 등 운영용 구간 |
| `top_factors` | 해당 예측에 크게 작용한 변수 |
| `model_version` | 재현성 확보를 위한 모델 버전 |

### 1.3 핵심 개발 전략

1. 라벨 의미와 데이터 전처리 이력을 먼저 확인한다.
2. 극심한 불균형 데이터이므로 Accuracy를 주 지표로 사용하지 않는다.
3. 더미 기준선과 로지스틱 회귀를 만든 뒤 XGBoost, CatBoost, LightGBM, ExtraTrees를 동일한 교차검증에서 비교한다.
4. 단일 성능 숫자가 아니라 PR-AUC, 불량 재현율, 검사 예산별 Recall@K, 확률 보정, 반복 실험 분산을 함께 본다.
5. CN7/RG3 개별 모델·통합 모델·교차 제품 일반화를 모두 실험한다.
6. 최종 예측 확률을 검사 우선순위로 변환하고, FN/FP 및 불확실 사례를 분석한다.
7. 미라벨 데이터는 최종 추론과 분포 비교에 먼저 사용하고, 의사라벨은 후순위 실험으로만 수행한다.

### 1.4 권장 프로젝트 제목

모델을 아직 확정하지 않았으므로 특정 알고리즘 이름을 제목에 먼저 넣지 않는다.

> **제품군 일반화와 예측 불확실성을 고려한 비용민감형 사출품질 예측 및 동적 검사 우선순위 시스템**

대안:

> **불확실성 보정 기반 사출품질 사전예측 및 제한된 검사자원 우선순위 최적화**

## 3. 도메인 배경과 컬럼 해석 원칙

### 3.1 사출성형이란

사출성형은 열로 녹인 플라스틱 수지를 금형 내부에 높은 압력으로 주입하고, 냉각·고화한 뒤 금형을 열어 제품을 꺼내는 제조 방식이다.

일반적인 공정 흐름은 다음과 같다.

1. **금형 닫기(Clamping)**: 금형을 닫고 사출압력을 견딜 수 있도록 고정
2. **가소화(Plasticizing)**: 배럴 내부에서 수지를 가열하고 스크루 회전으로 용융·계량
3. **충전/사출(Filling/Injection)**: 용융 수지를 금형 캐비티에 주입
4. **보압(Holding/Packing)**: 수축을 보상하기 위해 압력을 유지
5. **냉각(Cooling)**: 제품이 형태를 유지할 정도로 고화
6. **금형 열기 및 취출(Mold Open/Ejection)**: 금형을 열고 제품 배출
7. **검사(Inspection)**: 외관, 치수, 중량, 변형, 미성형 등 확인

현재 데이터는 공정 종료 후의 최종검사 라벨과 공정 센서/설정값의 관계를 학습하는 정적 표 형식으로 보인다. 다만 행 하나가 정확히 제품 1개인지, 사이클 1회인지, 집계 구간인지 공식 확인이 필요하다.

### 3.2 컬럼의 기능적 묶음

아래 해석은 영문 컬럼명과 일반적인 사출성형 지식을 연결한 것이며, 정확한 센서 위치·단위·수집 방식은 미확인이다.

| 그룹 | 컬럼 | 일반적 의미 | 현재 확실성 |
|---|---|---|---|
| 시간 | `Injection_Time`, `Filling_Time`, `Plasticizing_Time`, `Cycle_Time`, `Clamp_Close_Time` | 사출·충전·가소화·전체 사이클·금형 닫기 소요시간 | 기능은 유력, 원 단위 미확인 |
| 위치 | `Cushion_Position`, `Plasticizing_Position`, `Clamp_Open_Position` | 스크루 잔량/계량/금형 열림 위치 | 기능은 유력, 센서 기준·단위 미확인 |
| 속도/RPM | `Max_Injection_Speed`, `Max_Screw_RPM`, `Average_Screw_RPM` | 사출 최대속도, 스크루 최대·평균 회전속도 | 기능은 유력, 원 단위 미확인 |
| 압력 | `Max_Injection_Pressure`, `Max_Switch_Over_Pressure`, `Max_Back_Pressure`, `Average_Back_Pressure` | 사출·전환·배압 관련 값 | 기능은 유력, 원 단위 미확인 |
| 온도 | `Barrel_Temperature_1`~`6`, `Hopper_Temperature`, `Mold_Temperature_3`, `4` | 배럴 여러 가열존, 호퍼, 금형 온도 채널 | 채널 의미는 유력, 물리적 위치·순서 미확인 |

### 3.3 `_숫자` 컬럼의 의미

`Barrel_Temperature_1`~`6`과 `Mold_Temperature_3`, `4`는 같은 값을 시간순으로 반복 측정한 컬럼이라기보다, **서로 다른 센서 구역 또는 채널**일 가능성이 높다. 예를 들어 배럴의 여러 히터 구간이나 금형의 서로 다른 위치일 수 있다.

단, 제공값이 컬럼별 표준화된 것으로 보이므로 현재 값의 단순 차이는 섭씨 온도 차이가 아니다. `Barrel_Temperature_1 - Barrel_Temperature_2` 같은 파생변수는 만들 수 있지만, 보고서에서는 **표준화 공간에서의 상대적 불균형**으로만 설명해야 한다.

### 3.4 음수 시간/RPM/압력 값의 해석

**[강한 정황]** 각 파일의 비상수 특성은 평균이 거의 0이고 모표준편차(`ddof=0`)가 거의 1이다. 따라서 음수 값은 실제 음수 시간이나 역회전을 뜻하기보다, 대략 다음 형태의 표준화 값일 가능성이 매우 높다.

\[
z = \frac{x - \mu}{\sigma}
\]

- 음수: 해당 파일/변환 기준 평균보다 낮은 값
- 0 근처: 평균과 비슷한 값
- 양수: 평균보다 높은 값

정확히 어떤 데이터로 평균·표준편차를 구했는지, 라벨/미라벨 파일마다 별도 변환했는지는 공식 확인이 필요하다. 원 단위 복원에 필요한 평균과 표준편차가 없으므로, 현재 상태에서는 “사출압력을 10 bar 낮춘다” 같은 물리 단위 처방을 만들 수 없다.

| 구성 | Labeled | Unlabeled |
|---|---:|---:|
| 이름 없는 첫 번째 인덱스 컬럼 | 있음 | 있음 |
| 공정 특성 | 24개 | 24개 |
| `PassOrFail` | 있음 | 없음 |
| 전체 컬럼 수 | 26개 | 25개 |

구조는 다음과 같다.

```text
Labeled   = [인덱스, PassOrFail, 공정 특성 24개]
Unlabeled = [인덱스,             공정 특성 24개]
```

- labeled: 공정 특성 \(X\)와 `PassOrFail` \(y\)를 이용한 지도학습 및 검증
- unlabeled: 학습 완료 모델의 확률 추론, 검사 우선순위 생성, 분포/OOD 분석
- 이름 없는 첫 컬럼: 양쪽에 모두 있지만 행 식별자 또는 저장 인덱스로 추정되므로 기본 모델 입력에서 제외
- 컬럼명이 같아도 분포가 같다는 뜻은 아니므로 labeled/unlabeled 분포 비교를 별도로 수행

#### 4.1.2 공정 특성 중복과 라벨 충돌 (v1.2)

**[데이터 확인]** ID와 라벨을 제외한 공정 특성 24개로 검사하면 다음과 같다.

| 파일 | 고유 특성 그룹 | 첫 행을 제외한 중복행 | 라벨 충돌 그룹 |
|---|---:|---:|---:|
| labeled CN7 | 606 | 605 | 11 |
| labeled RG3 | 591 | 591 | 25 |
| unlabeled CN7 | 28,771 | 6,468 | 해당 없음 |
| unlabeled RG3 | 29,707 | 6,234 | 해당 없음 |

- CN7: 605개 그룹이 각 2행, 1개 그룹이 1행이다. class_1을 포함한 그룹은 14개다.
- RG3: 591개 그룹 모두 각 2행이다. class_1 25행은 각각 동일 공정 특성의 class_0 행을 갖는다.
- 라벨 충돌은 동일 입력에서 0과 1이 함께 관측된다는 뜻이다. 라벨 오류나 인위적 복제라고 단정하지 않는다.
- 기본 분석에서 충돌 행을 삭제·수정하거나 다수결로 덮어쓰지 않는다. 원본 라벨을 보존한다.
- 동일 입력을 사용하는 결정적 모델은 충돌 행을 서로 구별할 수 없다. 이 정보 한계를 오류 분석에 포함한다.
- 그룹 정의는 파일 내 24개 공정 특성의 정확한 일치이며 ID와 라벨을 포함하지 않는다. 이 그룹이 실제 배치·로트라는 뜻은 아니다.
- 제품군 통합 실험 전에 파일 간 동일 특성도 검사하고, 최종 모델 입력 기준으로 동일 패턴이 분할 경계를 넘지 않도록 그룹 정의를 확정한다.

재현 명령(프로젝트 루트, `kamp-base` 환경):

```bash
python 1.injection-molding/scripts/data_audit.py
python -m unittest discover -s 1.injection-molding/tests -v
```

산출물은 `artifacts/audit/data_audit.json`, `labeled_feature_groups.csv`, `data_audit.md`이다.
SHA-256, 스키마, 결측/무한값, ID, 상수, 평균·표준편차, 중복·충돌 및 그룹 분할 가능성을 기록한다.
원본은 현재 `dataset/`에서 읽기 전용으로 관리한다. 이 스크립트는 Phase 1의 최소 진단이며 근접중복·파일 간 중복·분포 비교·상관 분석까지 완료한 것은 아니다.

### 4.2 표준화 정황

**[데이터 확인]** 각 CSV 내부에서 모든 비상수 특성의 평균은 사실상 0, 모표준편차(`ddof=0`)는 약 1이다.

**[강한 정황]** 네 CSV가 각각 별도로 표준화되었거나, 최소한 파일별로 평균 0·모분산 1에 가까운 통계를 갖도록 변환되었다. 이는 정규분포를 따른다는 뜻이 아니다.

이 정황은 다음 문제를 만든다.

1. 파일 간 값의 동일한 z-score가 동일한 원 단위를 뜻한다고 보장할 수 없다.
2. 라벨 파일과 미라벨 파일의 원 분포 차이가 표준화로 가려졌을 수 있다.
3. 원 단위 공정범위나 설정값을 복원할 수 없다.
4. 데이터 전처리 과정이 전체 파일을 사용했다면 평가 누수 여부를 별도로 검토해야 한다.

### 4.3 상수 및 분포 불일치 경고

**[데이터 확인]**

- `Clamp_Open_Position`은 라벨 CN7과 RG3에서는 각각 상수이다.
- 같은 컬럼은 미라벨 CN7과 RG3에서는 상수가 아니다.

의미:

- 이 특성은 라벨 데이터만으로는 불량과의 관계를 학습할 수 없다.
- 미라벨 데이터의 값 변화를 모델이 처음 보게 되는 구조이므로 분포 불일치 경고로 기록해야 한다.
- 기본 모델에서는 제거하고, 포함/제거 실험을 별도 수행한다.

### 4.4 현재 가장 중요한 미확인 사항

아래는 모델링 전에 해결해야 하는 **Gate 0** 항목이다.

1. `PassOrFail`의 0/1 중 어느 값이 불량인가?
2. CN7과 RG3는 제품, 금형, 설비, 공정조건 중 무엇을 구분하는가?
3. 행 하나의 생산 단위는 제품 1개, 사이클 1회, 배치, 또는 집계값 중 무엇인가?
4. 각 컬럼의 원 단위와 수집 시점은 무엇인가?
5. 표준화는 어떤 원본 집합과 통계로 수행했는가?
6. 현재 미라벨 데이터가 공식 테스트/추론 대상인지, 추가 학습용인지?

확인 경로:

- 공식 공고/첨부문서 재확인
- 데이터 다운로드 페이지의 메타데이터/설명 확인
- 주최 측 기술문의
- 답을 얻지 못하면 가정을 명시하고, 가정이 바뀌어도 동작하는 코드 구조 유지

폴더의 `04.-Guidebook_Molding.pdf`는 사용자가 구글 검색으로 찾은 유사 자료이며, 현재 대회 CSV와 일치하는 공식 데이터 사전으로 확인되지 않았다.

## 5. 문제 정의

### 5.1 예측 문제

- 입력 \(X\): 생산 건별 24개 공정 특성 + 검증된 경우 제품군 정보
- 목표 \(y\): 최종검사 결과의 정상/이상 이진 라벨
- 출력 \(p(y=\text{failure}\mid X)\): 이상/불량일 확률

**[데이터 확인]** `PassOrFail`에는 숫자 `0`과 `1` 두 값만 존재한다. 따라서 이 과제는 24개 공정 특성으로 두 클래스 중 하나를 예측하는 **지도학습 기반 이진분류 문제**이다. 이는 컬럼 이름만으로 판단한 것이 아니라 실제 고유값을 확인한 결과이다.

```text
Labeled 공정 특성 24개(X) + PassOrFail(y)
                    ↓ 학습
        이진분류 모델과 확률 보정기
                    ↓ 추론
Unlabeled 공정 특성 24개 → 클래스 확률 → 검사 우선순위
```

XGBoost, CatBoost, LightGBM은 분류와 회귀를 모두 지원하는 라이브러리이므로 이번 과제에서는 각각 `XGBClassifier`, `CatBoostClassifier`, `LGBMClassifier`와 이진분류 목적함수를 사용한다. 분류 결과 0/1만 출력하기보다 확률을 출력해야 검사 우선순위를 만들 수 있다.

### 5.2 운영 문제

검사 가능한 수량이 하루 생산량보다 적다고 가정하면, 상위 위험 건부터 검사해야 한다.

\[
\text{PriorityScore}_i = f(\hat p_i,\; u_i,\; o_i)
\]

- \(\hat p_i\): 보정된 불량 확률
- \(u_i\): 예측 불확실성
- \(o_i\): 학습분포 이탈(OOD) 점수

초기 버전은 보정된 불량 확률로만 정렬한다. 이후 불확실성과 OOD를 가중하는 정책을 별도 비교한다. 가중치는 임의로 정하지 않고 검증 데이터와 가정한 검사비용/미탐비용에 따라 선택한다.

### 5.3 연구 질문

1. 극심한 불균형 환경에서 어떤 모델이 가장 안정적으로 희귀 클래스를 찾는가?
2. CN7과 RG3를 개별 학습하는 것과 통합 학습하는 것 중 어느 쪽이 좋은가?
3. 한 제품군에서 학습한 패턴이 다른 제품군에도 일반화되는가?
4. 어떤 공정 변수와 변수 조합이 높은 위험과 연관되는가?
5. FN과 FP는 어떤 공정조건·제품군·분포 이탈 구간에서 집중되는가?
6. 상위 K%만 검사할 때 실제 이상 샘플의 몇 %를 포착할 수 있는가?
7. 확률 보정과 불확실성 정보가 검사 효율을 개선하는가?

### 5.4 LSTM·GRU 적용 여부

LSTM과 GRU는 순서가 있는 시퀀스에서 이전 시점의 정보를 학습하는 순환신경망 계열이다. 현재 CSV는 행마다 24개의 공정 요약 특성이 있는 표 데이터이며, 다음 사항이 확인되지 않았다.

- 행이 실제 생산 시간순으로 정렬되었는지
- 이름 없는 첫 컬럼이 생산순서인지
- 배치·로트·설비 중단 경계가 어디인지
- 연속된 여러 행이 동일 공정의 연속 사이클인지

따라서 현재 단계의 주 모델로 LSTM/GRU를 사용하지 않는다. 24개 서로 다른 공정 컬럼을 임의의 시간축으로 간주하거나, `Barrel_Temperature_1`~`6`을 시간 1~6으로 해석해 시퀀스를 만드는 것도 금지한다. 이 온도 컬럼들은 시간보다 서로 다른 센서 구역/채널일 가능성이 높다.

향후 공식 메타데이터를 통해 행의 시간순서와 배치 경계가 확인될 경우에만 다음 형태를 후속 실험으로 고려한다.

```text
이전 T개 연속 사출 사이클 × 매 시점 24개 특성
        → LSTM 또는 GRU
        → 현재/다음 사이클의 PassOrFail 확률
```

그 경우에도 시간순 분할, 제품군별 시퀀스 분리, 배치 경계 차단, 미래정보 누수 방지가 선행되어야 한다. 현재 2,393개 라벨과 희귀 클래스 42개 조건에서는 딥러닝 과적합 위험이 크므로 표 데이터 모델보다 실제 검증 성능이 개선될 때만 채택한다.

```mermaid
flowchart LR
```

2. PyTorch/TensorFlow/CUDA는 딥러닝 실험이 실제로 필요해질 때 별도 환경으로 분리한다.

4. `environment.yml`의 사용자별 `prefix:`는 공유 전에 제거한다.
5. 모든 실험은 seed, 입력파일 SHA-256, 코드 버전, 설정, 결과를 함께 기록한다.
6. 원본 데이터는 수정하지 않고, 모든 processed 파일은 코드로 재생성 가능해야 한다.

### 8.3 실행 인터페이스 목표

최종적으로 다음과 같은 단순한 실행 경로를 제공한다.

```bash
conda env create -f environment-base.yml  # 상위 프로젝트 루트에서 실행

python -m src.pipeline audit --config configs/base.yaml

python -m src.pipeline evaluate --config configs/base.yaml
python -m src.pipeline predict --config configs/base.yaml
```

명령 형태는 구현 과정에서 바뀔 수 있지만, 전처리부터 결과파일 생성까지 사람이 노트북을 수동으로 조작하지 않아도 실행되어야 한다.

## Phase 2. 검증 전략 고정

### 2.1 왜 일반 train/test split만으로 부족한가

숫자 클래스 1이 전체 42개뿐이므로 한 번의 분할 결과는 어떤 희귀 샘플이 test에 들어가느냐에 따라 크게 변할 수 있다. 단일 holdout의 좋은 점수만 보고 모델을 선택하면 불안정하다.

### 2.2 기본 검증안

공식 확인된 불량 라벨을 positive로 지정한다. 확인 전 탐색 실험은 `positive_label=1`인 class_1 예측으로 명시하고 불량 성능이라고 표현하지 않는다.

- 1차: 동일 공정 특성 그룹을 분리하는 `StratifiedGroupKFold`
- 최소 실행은 3 folds × 1 seed로 시작하고, 최종 반복 횟수와 seed 목록은 학습 성능을 보기 전에 고정한다.
- 5-fold 확대 여부는 희귀 클래스 포함 그룹 수와 각 fold의 클래스 분포를 기준으로 판단한다.
- 반복 시 명시적인 seed 목록으로 그룹 분할을 생성한다. 점수가 좋은 seed만 선택하지 않는다.
- 각 fold에서 train/validation 그룹 교집합이 비어 있는지, 양쪽에 두 클래스가 존재하는지 검사한다.
- 학습과 평가 모두 원본 행을 유지하며 충돌 그룹 전체를 한쪽에 배정한다.
- 하이퍼파라미터 탐색, early stopping, 보정기 학습, 임계값 선택의 내부 분할에도 그룹 분리 원칙을 적용한다.
- 랜덤 행 분할은 필요 시 진단용 보조 비교로만 사용하며 주 성능 근거로 사용하지 않는다.
- 모든 모델에 동일한 split index 사용
- 평균뿐 아니라 표준편차와 fold별 분포 보고
- hyperparameter 튜닝은 내부 CV 또는 엄격한 OOF 구조 사용
- threshold와 calibration도 평가 fold의 정답을 직접 보며 맞추지 않음

별도 제품군 모델에서는 positive 수가 매우 적으므로 3-fold와 5-fold의 안정성을 비교한다. fold당 positive 수를 항상 로그에 남긴다.

### 2.3 검증 실험 묶음

| 실험 | 학습 | 평가 | 목적 |
|---|---|---|---|
| A-CN7 | CN7 labeled | CN7 반복 층화 그룹 CV | CN7 내부 성능 |
| A-RG3 | RG3 labeled | RG3 반복 층화 그룹 CV | RG3 내부 성능 |
| B-Pooled | CN7+RG3 + 제품군 특성 | 통합 반복 층화 그룹 CV | 데이터 결합 효과 |
| C-Cross-1 | CN7 | RG3 | 제품군 일반화 |
| C-Cross-2 | RG3 | CN7 | 제품군 일반화 |
| D-Ablation | 주요 처리/특성 제거 | 동일 CV | 각 방법의 실제 기여 |

주의:

- CN7/RG3가 서로 다른 설비 또는 금형이면 랜덤 통합 CV만으로는 새 설비 일반화를 말할 수 없다.
- 파일별 별도 표준화가 의심되므로 교차 제품 실험의 해석에는 이 한계를 명시한다.
- 시간, 배치, 로트 정보가 추가로 발견되면 랜덤 CV보다 그룹/시간 기반 분할을 우선한다.

### 2.4 검증 설계 고정 산출물

- `docs/validation_protocol.md`
- split 생성 seed와 각 fold 클래스 수

한 번 공식 실험을 시작한 뒤에는 split을 성능에 맞춰 바꾸지 않는다.

## Phase 3. 기준선 모델

### 목표

복잡한 모델이 실제로 단순 기준보다 나은지 판단할 최소 기준을 만든다.

### 모델

1. `DummyClassifier(strategy="prior")`
2. Logistic Regression: 기본 설정 및 class weight 효과 비교
3. 기본 XGBoost (`XGBClassifier`): 첫 비선형 baseline 후보
4. ExtraTrees: 후속 비교 후보

첫 baseline 비교는 Dummy prior → Logistic Regression → XGBoost 순서로 수행한다.
XGBoost를 처음부터 포함하되 우수성을 전제하지 않고 동일한 그룹 split에서 비교한다.
초기 XGBoost는 보수적인 깊이·트리 수와 고정 seed를 사용하고 대규모 튜닝은 하지 않는다.
`scale_pos_weight`를 쓰면 각 train fold의 클래스 수로 계산하며 미적용 모델과 비교한다.
GPU 사용 여부와 학습 성능 평가는 분리하며, GPU 호환성은 소규모 연산으로 검증 후 사용한다.
`DummyClassifier(strategy="stratified")`는 선택적인 무작위 비교로만 둔다.

### 처리

- 이름 없는 인덱스 제거
- 라벨 컬럼 분리
- 제품군 모델일 경우 `product_group` 추가
- 상수 컬럼 제거
- 현재 데이터가 이미 표준화된 정황은 있지만, 스케일링 여부는 Pipeline 안에서 비교
- 결측치는 현재 없지만 추론 안정성을 위해 명시적 처리 정책 유지

### 완료 조건

- 동일 split에서 모든 기준선의 OOF 확률 저장
- primary/secondary/ranking/calibration 지표 산출
- 학습시간과 추론시간 기록

## Phase 4. 후보 모델 비교 및 튜닝

### 4.1 후보군

| 계열 | 후보 | 역할 |
|---|---|---|
| 선형 | Logistic Regression | 해석 가능하고 과적합이 비교적 적은 기준 |
| 배깅 | Random Forest, ExtraTrees | 비선형성과 상호작용 탐색 |
| 부스팅 | XGBoost, CatBoost, LightGBM | 표 데이터 주력 성능 후보 |
| 앙상블 | 확률 평균/가중 평균 | 모델 간 오류 상보성 활용 |

딥러닝은 2,393개의 라벨과 42개의 희귀 클래스 조건에서 기본 선택이 아니다. 특히 시간순서가 확인되지 않았으므로 LSTM/GRU를 단순히 적용하지 않는다. 충분한 데이터 구조 근거와 검증 개선이 있을 때만 후순위로 추가한다. LLM도 예측 모델의 필수 요소가 아니다.

### 4.2 부스팅 모델의 권장 시작 순서

현재 데이터가 소규모·수치형·극심한 불균형 표 데이터라는 점을 고려해 다음 순서로 구현한다.

| 시작 순서 | 모델 | 현재 과제에서의 역할 | 핵심 주의점 |
|---:|---|---|---|
| 1 | XGBoost | 첫 번째 주력 후보 | 깊이·정규화·부분표본 설정으로 작은 데이터 과적합 제어 |
| 2 | CatBoost | 주력 비교 후보 | 범주형 장점은 적지만 균형 가중치와 안정적 기본 설정 활용 |
| 3 | LightGBM | 추가 비교·앙상블 후보 | leaf-wise 성장으로 작은 데이터에 과적합하지 않게 복잡도 제한 |

이 순서는 최종 성능 순위를 미리 결정한 것이 아니라 **구현 시작 순서**이다.

- XGBoost: 수치형 특성, 작은 데이터, 다양한 정규화 옵션을 고려해 첫 주력 후보로 사용
- CatBoost: `auto_class_weights="Balanced"` 등을 활용해 같은 split에서 비교
- LightGBM: `num_leaves`, `max_depth`, `min_child_samples`를 보수적으로 제한해 비교
- 학습속도는 현재 2,393행 규모에서 중요한 선택기준이 아님

초기 공식 비교 세트는 다음으로 고정한다.

```text
DummyClassifier
Logistic Regression
ExtraTrees
XGBoost
CatBoost
LightGBM
```

초기 비교 후 상위 2개 모델만 세밀하게 튜닝한다. 두 모델의 오류가 상보적이면 보정 확률의 평균/가중평균 앙상블을 추가한다.

### 4.3 불균형 처리

우선순위:

1. class weight / `scale_pos_weight`
2. 임계값 최적화
3. 확률 보정
4. bagging/ensemble
5. oversampling 또는 SMOTE는 ablation으로만 비교

주의:

- SMOTE를 전체 데이터에 먼저 적용하면 검증 누수이다. 학습 fold 내부에서만 수행한다.
- 표준화된 공정 공간에서 생성된 합성 샘플이 물리적으로 가능한 공정조건인지 보장할 수 없다.
- 단순 정확도를 높이기 위해 희귀 클래스를 무시하는 모델은 탈락시킨다.

### 4.4 튜닝 원칙

- Optuna 또는 RandomizedSearchCV 사용 가능
- 작은 데이터에 맞게 탐색공간 제한
- 모델당 동일하거나 합리적으로 비교 가능한 계산 예산 부여
- primary metric과 safety metric을 동시에 만족해야 채택
- best single fold가 아니라 repeated CV 평균·분산으로 선택
- 튜닝 로그와 전체 trial 결과 저장

### 4.5 모델 선택 규칙 예시

1. 평균 PR-AUC가 기준선보다 유의미하게 높음
2. 목표 검사예산에서 Recall@K가 우수함
3. 희귀 클래스 Recall의 반복 실험 하위구간이 지나치게 낮지 않음
4. calibration 후 Brier score가 허용 범위
5. CN7/RG3 중 한쪽만 극단적으로 실패하지 않음
6. 설명과 재현이 가능함

최종 선택은 특정 모델을 미리 정해 놓고 정당화하는 방식이 아니라, 이 규칙에 따라 결정한다.

## Phase 5. 특성공학과 ablation

### 5.1 원본 특성 우선

먼저 원본 24개 특성만으로 기준 성능을 만든다. 이후 도메인 기반 파생특성이 실제로 성능을 높이는지 비교한다.

### 5.2 후보 파생특성

**[가설]**

- 시간 계열 묶음의 합/평균/최댓값
- `Cycle_Time`과 세부 시간들의 상대 관계
- 최대 RPM과 평균 RPM의 표준화 공간 차이
- 최대 배압과 평균 배압의 표준화 공간 차이
- 사출압력과 전환압력의 상대 차이
- 배럴 6개 존의 표준화 평균·표준편차·범위
- 금형온도 채널의 표준화 차이
- 압력×속도, RPM×가소화시간 등 제한된 상호작용

### 5.3 금지 또는 주의

- 원 단위가 없는 상태에서 z-score 간 비율은 분모가 0 근처일 수 있고 물리적 의미도 약하므로 지양
- 모든 조합을 무차별 생성해 작은 라벨 데이터에 과적합하지 않음
- 파생특성은 fold 내부에서 생성 가능한 결정적 변환으로 구현
- “온도 차이가 5도”처럼 원 단위로 해석하지 않음

### 5.4 ablation 표

| 실험 | 제거/추가 요소 | 확인하려는 것 |
|---|---|---|
| F0 | 원본 24개 | 기준 |
| F1 | 상수 컬럼 제거 | 노이즈 제거 효과 |
| F2 | 도메인 파생특성 추가 | 공정 지식 기여 |
| F3 | 제품군 특성 추가 | CN7/RG3 정보 기여 |
| F4 | class weight 제거 | 불균형 처리 기여 |
| F5 | calibration 제거 | 확률 신뢰도 기여 |
| F6 | uncertainty 제거 | 우선순위 정책 기여 |

## Phase 6. 평가지표

### 6.1 분류 성능

#### 주 지표

- **Average Precision(AP)**: 초기 모델 비교의 주 지표. 사다리꼴 적분 PR-AUC와 구분하여 저장한다.
- **Recall (불량 재현율)**: 실제 불량 중 찾아낸 비율
- **Precision**: 불량으로 경고한 것 중 실제 불량 비율
- **F1 및 필요 시 F\(\beta\)**: F1은 기본 비교표에 포함하며 positive label, averaging, threshold를 기록한다.
- **MCC**: 불균형 데이터에서 전체 혼동행렬을 반영

#### 보조 지표

- ROC-AUC
- Balanced Accuracy
- Specificity
- FNR: 불량을 정상으로 놓친 비율
- FPR: 정상을 불량으로 잘못 경고한 비율

Accuracy는 참고만 한다. 모두 정상으로 예측해도 약 98%가 나올 수 있어 주 지표로 부적절하다.

### 6.2 검사 우선순위 성능

검사 예산을 전체의 K%라고 할 때:

- `Recall@K`: 상위 K% 검사로 전체 불량 중 몇 %를 포착하는가
- `Precision@K`: 상위 K% 중 실제 불량 비율
- `Lift@K`: 무작위 검사 대비 불량 발견 효율
- 목표 Recall 달성에 필요한 검사 비율
- 누적 이득(Cumulative Gains)과 Lift curve

예시 검사예산: 상위 1%, 3%, 5%, 10%, 20%. 실제 현장 검사능력이 확인되면 그 값으로 갱신한다.
K는 비율인지 건수인지 구분하고 반올림 규칙을 고정한다. 동일 점수는 정답과 독립적인 고정 seed의 무작위 우선순위로 처리하고 동점 규모를 기록한다. 원본 ID/행 순서가 우연히 라벨 순서를 반영해 성능을 높이지 않도록 한다.

### 6.3 확률 품질

- Brier score
- Log loss
- Calibration curve / reliability diagram
- Expected Calibration Error(ECE, 구현 정의 명시)

검사 순위만 맞더라도 확률이 과신되어 있으면 운영 임계값을 잘못 정할 수 있으므로 calibration을 별도 평가한다.

### 6.4 불확실성

- 반복 CV/부트스트랩/모델 앙상블의 예측 분산
- confidence interval
- uncertainty 상위 구간의 오류율
- risk-coverage curve: 확신이 낮은 샘플을 사람에게 넘길 때 남은 자동판정 성능

### 6.5 보고 방식

- 평균 ± 표준편차
- 가능하면 동일 특성 그룹을 재표집하는 bootstrap 95% 신뢰구간. 반복 OOF 행과 fold 점수를 독립 관측처럼 세지 않으며 재표집 단위·추정 대상을 명시한다.
- fold별 점 분포
- 전체뿐 아니라 CN7/RG3별 표
- threshold-free 지표와 운영 threshold 지표를 구분

## Phase 7. 확률 보정·임계값·의사결정

### 7.1 확률 보정

비교 후보:

- Platt/sigmoid calibration
- Isotonic calibration(표본이 작아 과적합 위험)
- 필요 시 beta calibration을 추가 실험

보정기는 모델을 학습한 데이터와 분리된 예측에 적합해야 한다. 외부 평가 fold는 보정·임계값 선택에 사용하지 않는다.
외부 train 내부의 그룹 OOF로 보정기와 임계값을 결정하고 외부 validation에서 평가한다.
보정기를 학습한 OOF 정답으로 보정 성능을 다시 평가하지 않는다.
미라벨 데이터의 보정 품질은 정답 없이 검증할 수 없으며, 단조 보정이 순위 개선을 보장하지 않는다.

### 7.2 임계값 선택

0.5를 자동으로 사용하지 않는다. 아래 운영 가정 중 하나로 결정한다.

- 불량 Recall 최소 90%를 만족하는 임계값
- FNR 비용이 FPR 비용보다 큰 비용함수 최소화
- 일일 검사 가능량 K%를 만족하는 순위 기반 정책
- 불확실하거나 OOD인 경우 자동판정 대신 재검사

현장 비용을 알 수 없으면 여러 시나리오를 표로 제시한다.

### 7.3 검사 우선순위 정책 후보

1. **Risk-only**: 보정 불량확률 내림차순
2. **Risk + uncertainty**: 고위험 또는 불확실한 샘플 우선
3. **Risk + OOD**: 고위험 및 학습분포 밖 샘플 재검사
4. **Tiered policy**:
   - A: 즉시 검사
   - B: 우선 검사
   - C: 표본 검사
   - D: 일반 흐름

정책별 Recall@K, Precision@K, 검사량, 미탐 수를 비교한다.

## Phase 8. 설명가능성·영향요인·오류 분석

### 8.1 전역 설명

- permutation importance
- SHAP summary/bar/beeswarm
- PDP 또는 ALE
- 상위 변수 상호작용
- 제품군별 중요도 비교

주의:

- 중요도는 인과관계가 아니다.
- 강하게 상관된 변수 사이에서는 중요도가 분산될 수 있다.
- 표준화된 값으로 해석하므로 원 단위 조건처럼 표현하지 않는다.

### 8.2 개별 설명

각 고위험 샘플에 대해:

- 예측확률
- 불확실성
- 상위 양/음 방향 기여 변수
- 학습분포 내 위치
- 비슷한 라벨 샘플(선택)

작업자가 원시 SHAP 값만 보지 않도록 짧은 자연어 설명 템플릿을 만든다.

예:

> 이 샘플은 평균 대비 높은 사출압력 관련 값과 배럴 존 간 상대 편차가 함께 관측되어 위험 순위가 상승했습니다. 단, 현재 값은 표준화 값이며 물리 단위의 원인으로 확정할 수 없습니다.

### 8.3 FN 분석

FN은 실제 불량을 놓친 사례이므로 가장 중요하다.

- CN7/RG3별 FN 비율
- 변수 분위수별 FN 집중 구간
- 불확실성·OOD와 FN 관계
- 정상 클래스 밀집 영역에 섞인 불량인지
- 특정 모델만 놓치는지, 모든 모델이 놓치는지
- 라벨 오류 또는 측정 누락 가능성

### 8.4 FP 분석

- 어떤 정상 공정조건을 불량으로 오인하는지
- 특정 제품군/극단값에서 경보가 과도한지
- 현장 검사부담 증가량
- 확률 보정이나 임계값 조정으로 줄어드는지

### 8.5 모델이 잘 작동하는 조건

- 제품군별
- 확률 구간별
- 불확실성 구간별
- 각 주요 특성의 중앙/극단 분위수별
- 학습분포 근접/이탈별

최종 보고서에는 성공조건과 실패조건을 동일한 구조의 표로 제시한다.

## Phase 9. 미라벨 데이터 활용

### 9.1 우선 사용처

1. 공식 추론/제출 결과 생성
2. 라벨 데이터와의 분포 비교
3. 고위험 샘플 검사 우선순위 생성
4. OOD 탐지 기준 수립
5. 모델 예측 일치/불일치 분석

### 9.2 의사라벨·준지도학습

준지도학습은 기본 모델을 완성한 뒤 별도 실험으로만 수행한다.

허용 조건:

- 높은 신뢰도와 낮은 불확실성을 동시에 만족하는 샘플만 선택
- class imbalance를 악화시키지 않는 규칙
- pseudo-label 포함/미포함 ablation
- 기존 labeled 반복 CV에서 개선 여부 검증
- 개선이 재현되지 않으면 최종 모델에서 제외

금지:

- 미라벨 예측을 정답처럼 사용해 성능 보고
- 한 번의 모델 예측을 그대로 대량 학습 데이터로 추가
- 미라벨 파일에서 fitting한 전처리를 검증 fold에 누수

### 9.3 `Clamp_Open_Position` 처리

라벨 데이터에서는 상수이므로 기본 학습 특성에서 제외한다. 미라벨에서 변하는 사실은 OOD/데이터 수집 차이 경고로 기록한다. 이 특성의 불량 영향은 현 라벨 데이터만으로 평가할 수 없다.

## Phase 11. 현장 적용 시나리오

### 11.1 운영 흐름

```text
사출 사이클 종료
  → 공정값 수집 및 schema 검증
  → 불량확률·불확실성 계산

  → 조건 충족 시 재학습
```

### 11.2 사용자에게 보여줄 정보

- 현재 위험등급과 순위
- 위험확률(보정 여부 표시)
- 불확실성 경고
- 주요 관련 공정 변수
- 권장 조치: 즉시검사/우선검사/일반검사
- 모델 버전과 예측 시각

### 11.3 공정조정 제안의 한계

현재 데이터는 표준화 값이고 원 단위·제어범위가 확인되지 않았다. 따라서 다음 수준으로 제한한다.

- 가능: “특정 변수의 표준화 상위 구간에서 위험이 증가하는 연관성이 관측됨”
- 가능: “해당 구간을 우선점검하고 원 단위 이력과 비교할 필요가 있음”
- 금지: “온도를 X°C 낮추면 불량이 감소한다”와 같은 검증되지 않은 인과 처방

실제 setpoint 조정은 공정전문가 검토와 안전한 소규모 실험을 거쳐야 한다.

## 13. 팀 작업 분담안

팀원 수에 맞게 한 사람이 여러 역할을 맡을 수 있다.

| 작업축 | 책임 |
|---|---|
| 데이터·도메인 | 데이터 사전, 공식 문의, EDA, 공정 배경 |
| 모델·검증 | split, 기준선, 튜닝, calibration, 지표 |
| 오류·설명 | SHAP/Permutation, FN/FP, OOD, 일반화 |
| 제품화·문서 | 파이프라인, 테스트, README, 보고서, 발표자료 |

공유 원칙:

- 공통 split과 metric 함수를 모든 팀원이 사용
- 각자 별도 노트북 결과를 수동 취합하지 말고 artifacts 형식을 통일
- 모델 비교 전 preprocessing 규칙을 합의
- 성능 수치는 실행 ID와 함께 공유

- [ ] split 파일 저장
- [ ] primary metric과 검사예산 정의
- [ ] threshold 선택 규칙 정의

- [ ] 기준선 + 최소 2개 후보 동일 조건 비교

- [ ] 불확실/OOD 처리 규칙 정의

### Gate 5 — 제출 준비 완료

|---|---|---|

| 확률 미보정 | 운영 임계값 오류 | OOF calibration, Brier/ECE 평가 |
| SHAP의 인과 해석 | 잘못된 공정 처방 | 연관성 표현, 원 단위 확인 전 조정 금지 |
| 미라벨 의사라벨 오염 | 오류 강화 | 후순위·고신뢰 샘플·ablation |
| LLM의 근거 없는 구현 | 조용한 오류 | 단계별 승인, 테스트, 결과 로그, 사실 등급 유지 |

## 18. LLM 코딩 에이전트 작업 규칙

이 문서를 받은 LLM은 다음을 지켜야 한다.

1. 한 번에 전체 과제를 임의 구현하지 말고 Phase 단위로 진행한다.
2. 각 Phase 시작 전에 입력, 변경 파일, 예상 산출물, 검증방법을 짧게 제시한다.
3. `data/raw`는 수정하지 않는다.
4. `PassOrFail`의 의미를 추측해 확정하지 않는다.
5. CN7/RG3, 단위, 센서 위치를 근거 없이 만들어내지 않는다.
6. 가이드북을 현재 데이터의 공식 설명서로 취급하지 않는다.
7. 전처리 fit은 train fold 안에서만 수행한다.
8. 지표는 fold 평균·분산과 함께 저장한다.
9. accuracy 단독으로 모델을 평가하지 않는다.
10. 모든 결과는 재실행 가능한 코드로 생성한다.
11. 파일을 수정한 뒤 관련 테스트와 smoke test를 실행한다.
12. 실패하거나 확인되지 않은 항목을 숨기지 않고 기록한다.
13. 모델 성능 향상이 없으면 복잡한 기법을 제거한다.
14. 원 단위가 없는 값을 실제 공정 설정값으로 해석하지 않는다.
15. 외부 데이터나 패키지를 추가하기 전에 목적·라이선스·재현성 영향을 알린다.
16. 시간순서와 배치 경계가 확인되기 전에는 LSTM/GRU 입력 시퀀스를 임의로 만들지 않는다.

### 18.1 LLM에게 처음 보낼 권장 프롬프트

```text
첨부한 설계서를 이 프로젝트의 기준 문서로 사용해줘.

우선 Phase 0과 Phase 1만 수행해. 아직 모델 학습은 시작하지 마.
현재 저장소와 데이터 파일을 읽고 다음을 해줘.

1. 프로젝트 폴더 구조를 점검하고 필요한 최소 골격을 제안한다.
2. 원본 CSV를 수정하지 않는 자동 data-audit 코드를 만든다.
3. 파일별 shape, schema, dtype, 결측, 중복, 라벨 분포, 상수 컬럼,
   인덱스 특성, 표준화 정황, CN7/RG3 및 labeled/unlabeled 분포 차이를 검사한다.
4. 데이터 누수 가능성과 아직 확인되지 않은 의미를 분리해 보고한다.
5. data_audit.json, 표와 그림, data_contract 초안을 만든다.
6. 테스트를 실행하고 결과를 요약한다.

중요 규칙:
- PassOrFail의 0/1 의미를 추정해 확정하지 않는다.
- 04.-Guidebook_Molding.pdf는 유사 참고자료이며 공식 데이터 사전이 아니다.
- 이름 없는 첫 컬럼을 모델 특성으로 자동 사용하지 않는다.
- 데이터가 이미 표준화되었다고 단정하지 말고 통계적 근거와 한계를 함께 쓴다.
- Phase 1 결과를 내가 확인하기 전 Phase 2 이후로 넘어가지 않는다.
```

### 18.2 각 단계 완료 보고 형식

## 19. 최초 실행 순서

설계서 작성 후 실제로 가장 먼저 할 일은 다음과 같다.

1. 이 문서를 프로젝트 루트에 둔다.
2. Git 저장소를 초기화하거나 기존 저장소 상태를 확인한다.
3. 현재 `dataset/`의 네 CSV를 원본으로 보존한다. 경로를 바꾸면 코드·문서도 함께 갱신하고 중복 원본을 관리하지 않는다.
4. 파일 SHA-256 manifest를 만든다.
5. 공식 문의가 필요한 질문 목록을 확정한다.
6. `00_data_audit` 또는 동등한 스크립트를 구현한다.
7. 자동 audit 결과를 팀과 검토한다.
8. 라벨 의미를 확인한 뒤 validation protocol을 고정한다.
9. Dummy/Logistic/XGBoost를 동일한 그룹 분할에서 초기 baseline으로 비교한다.
10. ExtraTrees, CatBoost, LightGBM을 같은 split에서 추가 비교하고 우수 후보를 튜닝한다.
11. 모델 이름이 아니라 PR-AUC, 희귀 클래스 Recall, Recall@K, 반복 검증 분산으로 상위 2개를 선정한다.

즉, 첫 목표는 “고성능 모델 만들기”가 아니라 **틀린 데이터 해석과 검증 누수를 막는 신뢰 가능한 실험 기반을 만드는 것**이다.

## 20. Definition of Done

다음 조건을 모두 만족할 때 과제가 완료된 것으로 본다.

- [ ] 공식 요구사항과 제출 형식을 모두 충족한다.
- [ ] 라벨 및 데이터 가정이 명시되어 있다.
- [ ] 기준선과 최소 2개 이상의 후보 모델을 동일 검증에서 비교했다.
- [ ] PR-AUC, Recall, Precision, MCC, FNR/FPR을 보고했다.
- [ ] 검사예산별 Recall@K, Precision@K, Lift@K를 보고했다.
- [ ] 확률 보정과 불확실성을 평가했다.
- [ ] CN7/RG3별 결과와 교차 제품 일반화를 분석했다.
- [ ] FN/FP 실패조건을 구체적으로 분석했다.
- [ ] 중요 변수와 상호작용을 인과로 과장하지 않고 설명했다.
- [ ] 현장 검사 우선순위 정책을 제안했다.
- [ ] 미라벨 전체에 대한 예측파일을 정확한 행 순서로 생성했다.
- [ ] 새 환경에서 전처리부터 추론까지 자동 재실행된다.
- [ ] README만 보고 제3자가 결과를 재현할 수 있다.
- [ ] 보고서·발표자료·코드에 소속·학교명·로고가 없다.
- [ ] 제출 전 파일을 실제로 다시 열어 손상·누락·개인정보를 확인했다.
